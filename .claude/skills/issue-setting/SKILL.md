# Issue Setting（AI時代の判断フレームワーク）

AIは解の質は高いが、イシュー度の低い問題を高品質に解いてしまう。**イシュー度を吟味する前に解きに行かない**ことが本フレームワークの核心。

## いつ使うか

- 新規施策・プロジェクトの着手可否判断
- 複数選択肢から優先順位を決めるとき
- 「これ重要？」「今やるべき？」と迷ったとき
- 会議の論点設定、投資判断
- AIエージェントに何をやらせるかの設計時

使わない場面:
- 単純な作業指示の実行
- 事実確認・情報検索
- 既に方針が決まっている作業

## 4フェーズ

### 1. センサー（一次情報取得）
- このイシューの**一次情報**は何か？誰に聞けば取れるか？
- 数値に現れる前の違和感は何か？
- AIに任せられる部分: インタビュー設計、仮説リスト、欠損指摘
- 人間が取る部分: 取得そのもの、本音の把握

### 2. 翻訳（情報を繋ぐ）
- 複数の一次情報に**共通構造**はあるか？
- 人間の直感 ↔ AIの検証 のラリーで仮説を精緻化
- **最も投資対効果が高いフェーズ**

### 3. 目利き（イシュー度の判断）
- このイシューは本当に重要か？**重要でない可能性を敢えて論じる**
- バリュー = イシュー度 × 解の質 の式に当てはめると？
- AIを「答え」でなく「壁打ち相手」として使う

### 4. 決断（不完全情報での意思決定）
- 可逆 / 不可逆の仕分け
- 不可逆なら「間違っていた場合、最初に見えるシグナル」を事前定義
- 撤退条件を先に書く

## 出力テンプレート

判断を下す際は以下の形で回答:

```
## 判断: <やる / やらない / 情報不足>

### センサー
- 一次情報: <取得済 / 未取得（取得先: ...）>
- 違和感: ...

### 翻訳
- 共通構造: ...
- 仮説: ...

### 目利き
- イシュー度: <高 / 中 / 低> — 理由: ...
- 重要でない可能性: ...

### 決断
- 可逆性: <可逆 / 不可逆>
- 撤退条件: ...
- 最初に見えるシグナル: ...
```

判断が重要・不可逆なら、結果を `workspace/decisions/` に意思決定ノートとして残す（`templates/decision.md` 準拠）。
