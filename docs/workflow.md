# 日々の進め方

PM-OS は「毎セッション同じ3手」で回す。慣れたら意識せず回るようになる。

---

## 1セッションの型

### 開始（現在地の把握）
- Claude に「現状を教えて」「今どこ？」と聞く。Claude は `workspace/_active-context.md` を読んで、優先事項・進行中・次アクションを返す。
- 特定 PJ を進めるなら「<PJ名> を進めたい」で該当ノートを読み込ませる。

### 作業（相談・判断・実行）
- 相談ごとはそのまま話す。判断が要る場面では Skill が自動で発動する:
  - **やるべきか / 優先順位** → `issue-setting`（センサー→翻訳→目利き→決断）
  - **根本原因→計画** → `decision-5step`（目標→問題→診断→設計→実行）
  - **曖昧な指示を検証可能に** → `goal-driven-execution`（受け入れ基準を先に固める）
- 会議をしたら「議事をまとめて」、何か決めたら「これを意思決定として残して」。

### 終了（状態の書き出し）
- 「今日のぶんを記録して」と言うと、Claude が:
  - `_active-context.md` を更新（完了を反映 / 次アクション追加 / 古い項目を削除）
  - 必要なら decisions / meetings / projects の各ノートを更新
- これで次のセッションの Claude が続きから動ける。

---

## 週次レビュー

週に一度、「週次レビューして」と言う。`decision-5step` の週次プロンプトが効いて、Claude が問う:

- 今週の目標は達成できたか
- **先週と同じ種類の問題を繰り返していないか**（繰り返していたら根本原因の再診断）
- 来週の優先事項

結果は `_active-context.md` の優先事項・次アクションに反映される。

---

## どこに何を書くか（迷ったとき）

| 内容 | 置き場所 |
|---|---|
| プロジェクトの状態・タスク・リスク | `workspace/projects/<名前>.md` |
| 決めたこと（選択肢・根拠・撤退条件込み） | `workspace/decisions/<名前>.md` |
| 会議の議事・アクションアイテム | `workspace/meetings/<日付-名前>.md` |
| 関係者の情報 | `workspace/people/<氏名>.md` |
| 今の全体の現在地 | `workspace/_active-context.md` |
| 分類が決まらないメモ | `workspace/inbox/` |

判断に迷ったら Claude に「これどこに書く？」と聞けばいい。

---

## コツ

- **状態をチャットに溜めない** — 大事なことは必ずノートに書き出させる。チャット履歴は消えても `workspace/` は残る。
- **決定は理由ごと残す** — 3か月後の自分が「なぜこう決めたか」を再現できるように。
- **`_active-context.md` を太らせない** — 詳細は各ノートへ。ここは現在地の一覧だけ。
- **Git にコミットする** — 区切りごとに `git add -A && git commit` しておくと、状態の履歴が残る。Claude に「コミットして」と頼んでもいい。
